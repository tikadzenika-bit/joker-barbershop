## 1. რა შენდება და რატომ

თბილისური ბარბერშოპების ქსელის, „JOKER Barbershop"-ის, ერთგვერდიანი საიტი სამ ენაზე (KA / EN / RU) და ადმინ პანელი, საიდანაც კლიენტი თვითონ ცვლის ფასებს, ფოტოებს, ბარბერებს და ფილიალებს.

- **ვისთვის:** თბილისში მცხოვრები და ჩამოსული მამაკაცები, რომლებიც ტელეფონიდან ეძებენ „ბარბერშოპი საბურთალოზე / ვაკეში", ნახულობენ ფასს, ირჩევენ ფილიალს და ეწერებიან.
- **მთავარი მოქმედება:** „ჩაწერა" → Altegio (სწორი ფილიალი). მეორე: „მოგვწერე WhatsApp-ზე".
- **რატომ ახლა:** კლიენტი ნამდვილია, საიტი გაეშვება; თან ეს Gridline-ის პორტფოლიოს მთავარი ნამუშევარი უნდა გახდეს.
- **ბრენდის სული:** „Peace | Friendship | Haircut" — თბილი, მეგობრული ხმა; თემა — ბანქოს ჯოკერი (კარტი, ♠ ♥ ♦ ♣, ჩარჩოები).

## 2. მიზნები, არა-მიზნები, ანტი-მიზნები

## 3. შეზღუდვები

- Vite + vanilla TypeScript, სტატიკური build; ჰოსტინგი Netlify / Vercel / GitHub Pages.
- Supabase უფასო tier: Auth (ელფოსტა + პაროლი), Postgres, Storage, RLS (საჯაროდ მხოლოდ კითხვა).
- ქართული, ლათინური და კირილიცა ერთნაირად კარგად უნდა გამოიყურებოდეს.
- `prefers-reduced-motion`, კონტრასტი 4.5:1, კლავიატურით ნავიგაცია, 44px შეხების ზონები.
- გვარები საიტზე არ იწერება. ფასები/ლოგო/ფოტოები კლიენტისგან მოვა — მანამდე placeholder, ადმინში ნიშნით „შესავსებია".

## 5. ტექნიკური მიდგომა

**არჩეული:** Vite + vanilla TypeScript, „static-first, live-refresh".
- `src/render/*` — სუფთა ფუნქციები `(content, lang) → HTML`. მათ იყენებს (ა) build — აგენერირებს მზა HTML-ს `/`, `/en/`, `/ru/`-ზე (SEO, hreflang, სწრაფი LCP) და (ბ) ბრაუზერი — იმავე ფუნქციებით ახლებს გვერდს, თუ შიგთავსი build-ის შემდეგ შეიცვალა.
- საჯარო JS მსუბუქია: ქცევები DOM-ზე მუშაობს; რენდერის მოდული მხოლოდ საჭიროებისას იტვირთება.
- საჯარო გვერდი Supabase-ს კითხულობს პირდაპირ REST-ით (`fetch`), `supabase-js` მხოლოდ ადმინშია.

**უარყოფილი:** Astro (ადმინის ცვლილების მყისიერი ჩვენებისთვის შაბლონები ორჯერ დასაწერი იქნებოდა); სუფთა SPA (ცარიელი HTML — ცუდი SEO და LCP).

**მონაცემები:** ერთი `Content` ობიექტი (`src/content/types.ts`): settings, texts, slides, categories→items, barbers, branches, gallery, reviews, faq. Supabase-ში — ცხრილი `content (collection, id, position, data jsonb)` + `admins` (ნებართვების სია, რადგან „ავტორიზებული" ≠ „ადმინი": Supabase-ში რეგისტრაცია ნაგულისხმევად ღიაა) + Storage bucket `media`. დემო რეჟიმში: `seed.json` + localStorage.

## 6. გვერდი სექციებად

1. **ჰედერი** — ლოგო, 6 ბმული, KA / EN / RU (არჩევანი ინახება; ენები ცალკე URL-ებია), „ჩაწერა". მობილურზე სრულეკრანიანი მენიუ (`<dialog>`).
2. **ჰერო-სლაიდერი, 5 სლაიდი = ხუთკარტიანი ხელი.** მარცხნივ უზარმაზარი სათაური, მარჯვნივ კარტი დასტაზე; სლაიდის ცვლისას კარტი „რიგდება". ① ჯოკერის კარტი + სლოგანი ② ფოტო-კარტი: შეჭრა და ფეიდი ③ ფოტო-კარტი: წვერი და პარსვა ④ „ხუთი ვარსკვლავის" კარტი: 4.9 ★ · 200+ ⑤ ფილიალების კარტები ცოცხალი „ღიაა ახლა"-თი. ავტო + პაუზის ღილაკი, ისრები, წერტილები, swipe, ← →.
3. **წითელი ლენტი** — სლოგანი სამ სიტყვად.
4. **სერვისები და ფასები** — „მენიუს ფურცელი" ორმაგი ჩარჩოთი: კატეგორია = ნიშანი (♠ თმა, ♣ წვერი და პარსვა, ♥ კომბო, ♦ ბავშვი, ★ დამატებითი); სახელი ····· ფასი, ქვეშ აღწერა და ხანგრძლივობა.
5. **ბარბერები** (შავი ზოლი) — კარტები 5:7, გადაბრუნება (hover / tap / focus): სპეციალობა, ენები, ფილიალი, „ჩაეწერე მასთან". ფილტრი ფილიალით. ფოტოს გარეშე — ტიპოგრაფიული „სასახლის კარტი" ინიციალით (სტოკ-სახეებს ნამდვილ სახელებს არ ვაწერთ).
6. **ფილიალები** — თითო: რუკა (OpenStreetMap, ჩვენს ფერებში + „ინტერაქტიული რუკა"), მისამართი, საათები + „ღიაა ახლა" (თბილისის დრო), ტელეფონი, WhatsApp, „მიმართულება", „ჩაწერა ამ ფილიალში".
7. **ნამუშევრები** — გალერეა + lightbox (swipe, ← →, Esc) + „მეტი Instagram-ზე".
8. **შეფასებები** (წითელი ზოლი) — 5 პერიფრაზირებული ციტატა ავტოსლაიდით + რეიტინგი.
9. **FAQ** — `<details>` აკორდეონი.
10. **ფუტერი / კონტაქტი** — ფილიალები, საათები, სოც. ქსელები, „საიტი: Gridline".
11. **მცურავი ზოლი მობილურზე** — „ჩაწერა" (ფილიალის არჩევა → Altegio) + WhatsApp.
