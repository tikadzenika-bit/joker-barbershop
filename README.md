## გაშვება ლოკალურად

საჭიროა [Node.js](https://nodejs.org) 22.18 ან უფრო ახალი.

```bash
npm install
```

```bash
npm run dev
```

გაიხსნება `http://localhost:5173` (ქართული), `/en/` და `/ru/`.

| ბრძანება | რას აკეთებს |
|---|---|
| `npm run dev` | dev სერვერი |
| `npm test` | ტესტები (ლოგიკა + რენდერი, 17 ტესტი) |
| `npm run build` | ტიპების შემოწმება + სტატიკური საიტი `dist/`-ში |

## როგორ არის აწყობილი

- **შიგთავსი ერთ ფაილშია:** `src/content/seed.json` — სლაიდები, სერვისები და ფასები, ბარბერები, ფილიალები, გალერეა, შეფასებები, FAQ და ყველა წარწერა სამ ენაზე. სტრუქტურა აღწერილია `src/content/types.ts`-ში.
- **შაბლონები:** `src/render/` — სუფთა ფუნქციები `(შიგთავსი, ენა) → HTML`. build-ის დროს `vite.config.ts`-ის პლაგინი მათ იძახებს და ქმნის მზა HTML-ს სამივე ენაზე (სწრაფი ჩატვირთვა, SEO).
- **ქცევები:** `src/site/main.ts` — სლაიდერი, მობილური მენიუ, „ღიაა ახლა" (თბილისის დრო), კარტის გადაბრუნება, ფილტრი, რუკა, lightbox, ფილიალის არჩევა.
- **სტილი:** `src/styles/site.css`. **ყველა ფერი `:root` ბლოკშია** — ლოგოს მოსვლისას მხოლოდ ის იცვლება.
- **ლოგიკა და ტესტები:** `src/lib/` + `tests/`.

## ადმინ პანელი

მისამართი: `/admin/` (ლოკალურად `http://localhost:5173/admin/`). ქართულია და ტელეფონიდანაც მოსახერხებელია. კლიენტისთვის დაწერილია ცალკე ფაილი: `კლიენტისთვის ინსტრუქცია.md`.

| რეჟიმი | როდის | შესვლა | სად ინახება |
|---|---|---|---|
| **დემო** | `.env`-ში Supabase-ის გასაღებები ცარიელია | პაროლის გარეშე | ამ ბრაუზერის localStorage (ფოტოებიც, შემცირებული) |
| **Supabase** | ორივე გასაღები შევსებულია | ელფოსტა + პაროლი | Postgres + Storage; ჩანს ყველა ვიზიტორისთვის |

გადართვა ერთი კონფიგით ხდება — `.env`.

- „შენახვის" შემდეგ ცვლილება საიტზე მაშინვე ჩანს; გახსნილი ჩანართი თვითონ ახლდება.
- „მთავარზე" არის ყველა „შესავსებია" ადგილის სია და „ექსპორტი / იმპორტი JSON" (ბექაპი).
- დემო რეჟიმში ბრაუზერის მეხსიერება შეზღუდულია: დაახლოებით 15–30 ატვირთული ფოტო.
- დემო საიტზე `/admin/` ყველასთვის ღიაა, მაგრამ ცვლილებები მხოლოდ იმ ადამიანის ბრაუზერში რჩება, ვინც შეცვალა.

## Supabase-ის დაკავშირება (ნაბიჯ-ნაბიჯ)

1. [supabase.com](https://supabase.com) → **New project** (უფასო გეგმა საკმარისია).
2. **SQL Editor** → ჩასვით `supabase/schema.sql`-ის მთელი შიგთავსი → **Run**. შეიქმნება ცხრილები `content` და `admins`, RLS წესები და ფოტოების საცავი `media`.
3. **Authentication → Sign In / Providers** → გამორთეთ **Allow new users to sign up**.
4. **Authentication → Users → Add user** → ელფოსტა და პაროლი, „Auto Confirm User" ჩართული.
5. **SQL Editor**-ში მიეცით ამ მომხმარებელს ადმინის უფლება (ჩაანაცვლეთ ელფოსტა):

```sql
insert into public.admins (user_id, note)
select id, 'მთავარი ადმინი' from auth.users where email = 'admin@example.com'
on conflict do nothing;
```

6. **Project Settings → API**-დან დააკოპირეთ `Project URL` და `anon public` გასაღები `.env` ფაილში (ნიმუში — `.env.example`):

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```

7. `npm run dev` → გახსენით `/admin/` → შედით → დააჭირეთ **„შენახვას"**. პირველი შენახვა ბაზას მიმდინარე შიგთავსით ავსებს.
8. ჰოსტინგზე იგივე ორი ცვლადი ჩაწერეთ **Environment variables**-ში და ააწყვეთ ხელახლა.

**უსაფრთხოება.** `anon` გასაღები საჯაროა და ბრაუზერში ჩანს — ეს ნორმალურია: ჩაწერას RLS უშვებს მხოლოდ `admins` ცხრილში მყოფი მომხმარებლისთვის, ხოლო Supabase-ში „ავტორიზებული" ნებისმიერი დარეგისტრირებული ადამიანია, ამიტომ მხოლოდ ავტორიზაცია საკმარისი არ იქნებოდა. `service_role` გასაღები **არასდროს** ჩაწეროთ `.env`-ში.

**როგორ ხვდება ცვლილება საიტზე.** ვიზიტორის ბრაუზერი ჩატვირთვისას ამოწმებს შიგთავსის ვერსიას და, თუ შეიცვალა, გვერდს ადგილზე ახლებს. Google კი ხედავს იმას, რაც ბოლო build-ის დროს იყო, ამიტომ დიდი ცვლილებების შემდეგ ააწყვეთ საიტი ხელახლა (Netlify / Vercel: „Trigger deploy") ან დააყენეთ ყოველდღიური ავტომატური build.

**ადმინის შესვლა.** ელფოსტა და პაროლი იქმნება მე-4 ნაბიჯზე. პაროლის შეცვლა: Supabase → Authentication → Users.

## ჰოსტინგი

საიტი სტატიკურია: `npm run build` → ატვირთე `dist/`.

- **Netlify:** დააკავშირე რეპო; `netlify.toml` უკვე გამზადებულია.
- **Vercel:** Framework = Vite, Build = `npm run build`, Output = `dist`.
- **GitHub Pages (ქვესაქაღალდეში):** ააწყე ასე და `dist/` ატვირთე `gh-pages` ტოტზე:

```bash
VITE_BASE=/joker-barbershop/ VITE_SITE_URL=https://<მომხმარებელი>.github.io npm run build
```

**საკუთარი დომენი:** `.env`-ში ჩაწერე `VITE_SITE_URL=https://დომენი.ge` (canonical, Open Graph და sitemap ამას იყენებს), ააწყე ხელახლა და დომენი მიაბი ჰოსტინგის პანელიდან.

## SEO

- სათაური და აღწერა სამივე ენაზე, `canonical`, `hreflang` (+ `x-default`), Open Graph, `sitemap.xml`, `robots.txt`.
- schema.org: თითო ფილიალი ცალკე `HairSalon` (`LocalBusiness`-ის ქვეტიპი; `BarberShop` ტიპი schema.org-ში არ არსებობს) მისამართით, კოორდინატებით, საათებით და `ReserveAction`-ით.
- `aggregateRating` განზრახ არ არის: Google კრძალავს სხვა საიტებიდან აღებული რეიტინგის მონიშვნას.
- ორივე მოქმედი მისამართი საბურთალოზეა, ამიტომ ტექსტში წერია „საბურთალო, ვაკესთან ახლოს" და არა „ვაკეში".
